# 测试与质量门禁

## 1. 测试金字塔

- 单元测试：领域规则、Schema、解析器、断言和状态机。
- 集成测试：SQLite、文件系统、Provider Stub、Worker 通信和 API。
- 端到端测试：从本地 FastAPI 用户入口串联 SQLite、工作空间文件、独立 Worker 和回环服务的核心闭环；
  桌面 UI 交互由 Vue 组件测试与 Electron 安装冒烟补充。
- 打包冒烟：安装、启动、升级、卸载和数据保留。

当前 Electron package 门禁额外验证：Electron ZIP 文件名与官方 SHA-256、PyInstaller Sidecar 构建、
Forge 有限时间成功退出、候选 resources 包含 Sidecar、ASAR 包含当前主进程和 Vite 入口、生产 renderer
使用 `app://ai-qa-assistant`、sandbox preload 成功注入最小 `desktopBridge`。Sidecar 冒烟覆盖自动迁移、
随机令牌鉴权、连续回环请求、父进程心跳丢失回收和冻结 `grpcio-tools` 分发。package 候选目录不能替代
M6 的干净虚拟机安装、升级、卸载、安装器与签名验证。

本地 API 网络隔离门禁同时覆盖：配置拒绝 `0.0.0.0`、局域网地址、IPv6 和主机名别名；开发入口只把
已验证的 `127.0.0.1` 传给 Uvicorn；真实桌面子进程启动后通过 Windows `netstat` 或 Linux
`/proc/net/tcp` 取证随机端口只有 `127.0.0.1` 监听；Electron 安装冒烟证据和 PowerShell 生命周期
门禁再次要求 `api_host` 为 `127.0.0.1`。测试不修改防火墙，也不依赖局域网中存在其他主机。

核心闭环端到端门禁使用临时工作空间与迁移到最新版本的临时 SQLite，并仅启动 `127.0.0.1` 上的
确定性 Ollama/业务 HTTP 服务。场景通过真实 FastAPI 路由完成工作空间创建、Markdown 需求导入与独立
解析 Worker、五维分析与独立模型 Worker、问题确认、测试点/用例生成和确认、带断言的独立 HTTP 执行
Worker，以及结构化/Markdown 报告校验；不访问外网、不读取系统模型凭据，也不复用预置业务记录。

Windows make 门禁进一步要求：Squirrel maker 成功退出；Setup.exe、full.nupkg 和 RELEASES 同时存在；
`SHA256SUMS.txt` 覆盖全部 maker 制品并可重新计算匹配；full.nupkg 内包含 Python Sidecar。当前只验证
未签名制品。安装生命周期模块先拒绝越界清单、重复制品、缺失文件和哈希不匹配；Windows CI 随后在
一次性 runner 中静默安装，启动已安装应用，并在 Sidecar 握手、数据库迁移和 renderer 加载完成后读取
受限临时目录中的 JSON 就绪证据，最后卸载并确认用户数据库按当前策略保留。未提供上一版本候选时升级
阶段明确记为 `skipped`，不得声称跨版本升级已通过。应用只接收系统临时目录内的绝对冒烟路径，脚本
随后把证据归档到调用者目录；Squirrel 卸载若留下墓碑，只允许 `.dead`、`Update.exe` 及当前版本目录
中的 `squirrel.exe`、`v8_context_snapshot.bin`、`vk_swiftshader_icd.json` 和 `vk_swiftshader.dll`，
门禁记录并清理这些测试残留，任何其他文件或目录均失败。

## 2. MVP 关键测试矩阵

### 工作空间

- 新建、重复名称、无权限目录、磁盘不足、路径被删除、版本迁移失败。

### 文档

- 正常导入、重复导入、损坏文件、超大文件、编码错误、不支持格式、路径穿越。

### AI

- Provider 不可用、超时、限流、结构化输出错误、引用缺失、用户取消、本地模式外发保护。

### 任务

- 排队、运行、进度、取消、超时、Worker 崩溃、UI 重启、重复事件和终态幂等。

当前 Markdown/TXT 切片已覆盖真实 `spawn` Worker 成功解析，以及失败、取消、超时、进程错误、
重启恢复和终态幂等的存储状态；文件测试覆盖不支持格式、超大文件、损坏 UTF-8、路径越界和哈希变化。

DOCX/PDF 切片增加：段落与表格顺序、PDF 页边界、空白文本层、加密 PDF、损坏 ZIP/PDF、提取文本
上限，以及真实 Worker 中 DOCX 成功和损坏 PDF 失败终态。

稳定引用切片增加：文本行段、DOCX 块和 PDF 页来源范围，字符偏移可回切全文，Worker 成功后事务写入，
文档作用域校验、引用响应 Schema、前端引用卡片，以及 `document_chunks` 迁移约束和旧全文回填。

批量导入切片增加：系统多选桥白名单、preload 拖拽路径解析、大小为 0 和超过 50 的请求、成功与业务失败
混合结果、意外异常脱敏、前端响应 Schema、Store 合并，以及选择和拖拽两种页面入口。

### 备份与诊断

- SQLite 在线备份可读取、完整性检查通过、包含业务记录，且不复制工作空间原文件或凭据。
- 诊断信息覆盖数据库版本、大小、完整性、工作空间数与备份数；存储异常返回稳定错误码且不泄露路径外的调试详情。
- 前端校验响应结构，展示备份范围，并在创建成功后刷新备份列表和诊断计数。

### HTTP/WebSocket/Protobuf

- 成功、连接失败、握手失败、超时、重连、乱序消息、二进制消息、解码失败、断言失败和敏感数据脱敏。
- Protobuf 资产切片覆盖工作空间路径边界、不支持格式、超限、损坏定义、重复内容、编译期间文件变化、
  本地 import 拒绝、内置 well-known type、迁移与重启恢复；编解码覆盖描述符版本不匹配、未知 JSON
  字段、无效 Base64 和损坏二进制。
- Protobuf 执行覆盖安全 URL、禁止重定向与系统代理、二进制响应上限、冻结描述符、请求编码、响应解码、
  严格类型字段断言、凭据脱敏，以及独立进程成功、启动失败、取消、总超时、崩溃与重启恢复。
- HTTP 还需覆盖四类断言、二进制断言限制、JSON 类型精确比较、仅幂等方法的传输故障重试、尝试上限、
  事件顺序与安全消息、终态重跑、环境删除后拒绝重跑，以及重跑后生成独立运行记录。
- WebSocket 需覆盖 ws/wss 映射、Origin 防替换、模板展开只发生在子进程、代理禁用、有序多消息发送/
  接收、文本与二进制、单条和总量上限、Ping 参数、最多一次受控重连及完整序列重放、四类断言与严格
  JSON 类型、脱敏和连接/接收超时；真实独立进程覆盖成功、断言失败、取消、Supervisor 超时、崩溃和
  进程参数无密钥。
- 统一任务事件流覆盖五类任务、工作空间隔离、子协议令牌认证、令牌不进入 URL/响应、首帧恢复、状态变化
  推送、单调序号去重、序号缺口恢复、异常断线退避重连、主动停止不重连，以及 Electron CSP 只开放
  `ws://127.0.0.1:*`。

### 报告

- 聚合规则覆盖最近 14 个 UTC 自然日边界、缺失完成时间排除、取消/进行中任务不进入通过率分母、
  平均时长和慢执行排序；分析、问题、测试点和用例统计必须按工作空间隔离。
- 本地确定性失败归因覆盖产品、环境、数据、脚本、未知五类，以及超时优先级、取消/通过排除、稳定
  规则 ID 和汇总一致性；归因不得读取错误正文或触发模型调用。
- JSON、Markdown、HTML 使用同一快照；覆盖敏感字段/Bearer/邮箱/手机号再次脱敏、Markdown 表格转义、
  HTML 注入转义，以及请求/响应正文和安全变量名称不进入报告。
- API 覆盖 schema v2、14 日趋势、归因汇总、成功、未知格式、工作空间不存在和意外异常脱敏；前端
  覆盖趋势长度/日期、归因分类/规则响应校验、切换工作空间后的旧响应丢弃、保存取消、保存失败和报告
  正文不进入 Pinia。
- Electron IPC 覆盖受信 sender、格式/媒体类型/扩展名匹配、文件名无路径分隔符、10 MiB 上限和系统
  保存对话框取消路径。

## 3. CI 门禁

Pull Request 至少执行：

- Ruff format check。
- Ruff lint。
- mypy。
- pytest（单元、集成与核心闭环端到端）。
- 前端 lint、typecheck、test、build。
- 依赖漏洞和密钥扫描。

M0 的 `.github/workflows/quality.yml` 分为后端、前端、Windows 桌面构建与安装生命周期、依赖审查和
密钥扫描任务。后端与前端依赖均使用锁文件，CI 安装时启用 frozen/locked 模式。验收 JSON 只保留在
临时 runner 中并由退出码形成门禁，不上传含本机路径的生命周期证据文件。成功的非 PR Windows
候选会将 Setup、NUPKG、RELEASES、SBOM、脱敏发布元数据和 SHA-256 清单归档到 GitHub Actions
90 天，制品名包含 workflow run ID。
工作流除 push/PR 外还支持 `workflow_dispatch`，用于从 GitHub Actions 界面对已经推送的候选引用手动
重跑完整门禁。默认 `internal` 模式允许生成明确标记的未签名内部候选；选择 `formal` 时必须同时
配置正式 PFX 与口令 Secret，并额外强制校验 Setup 和更新包中全部 PE 文件的 Authenticode 签名与
可信时间戳。`codex/release-*` 候选分支的 push 也会直接运行完整工作流，便于合并前取得干净 runner
结果。手动入口或触发成功本身不构成通过证据，仍以对应运行的各 Job 结论为准。
下一版本手动验收时可填写上一候选的正整数 run ID；工作流只从当前仓库下载固定名称的候选归档，
校验清单后把目录传给 `-PreviousArtifactRoot`，执行上一版本安装、首次启动、当前版本升级和卸载。

提交 `f6c3f02` 对应的 [Quality run 32873435673](https://github.com/eudifnai/AI-QA-Assistant/actions/runs/32873435673)
已在 GitHub hosted Windows runner 通过 make、制品 Validate、真实安装、Sidecar/Alembic/renderer
就绪、卸载和用户数据库保留；同次运行的后端、前端和密钥扫描也通过。归档
`windows-release-candidate-32873435673` 保留至 2026-11-23。该证据不替代 formal Authenticode、
独立 VM SmartScreen、重复安装或跨版本升级门禁。

主分支或 Release Tag 增加：

- 安装包冒烟。
- 数据库升级路径测试。
- SBOM、校验和和签名。

## 4. 发布 Gate

No-Go 条件：

- P0/P1 缺陷未关闭。
- 数据迁移不可恢复或未验证。
- 安装包无法在干净环境启动。
- 本地模式存在隐式云端请求。
- API Key 或敏感日志泄露。
- 核心闭环无端到端验证。
- 质量命令失败且无正式豁免记录。
