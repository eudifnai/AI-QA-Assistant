# 测试与质量门禁

## 1. 测试金字塔

- 单元测试：领域规则、Schema、解析器、断言和状态机。
- 集成测试：SQLite、文件系统、Provider Stub、Worker 通信和 API。
- 端到端测试：桌面 UI 到本地 FastAPI 的核心用户闭环。
- 打包冒烟：安装、启动、升级、卸载和数据保留。

## 2. MVP 关键测试矩阵

### 工作空间

- 新建、重复名称、无权限目录、磁盘不足、路径被删除、版本迁移失败。

### 文档

- 正常导入、重复导入、损坏文件、超大文件、编码错误、不支持格式、路径穿越。

### AI

- Provider 不可用、超时、限流、结构化输出错误、引用缺失、用户取消、本地模式外发保护。

### 任务

- 排队、运行、进度、取消、超时、Worker 崩溃、UI 重启、重复事件和终态幂等。

### HTTP/WebSocket/Protobuf

- 成功、连接失败、握手失败、超时、重连、乱序消息、二进制消息、解码失败、断言失败和敏感数据脱敏。

## 3. CI 门禁

Pull Request 至少执行：

- Ruff format check。
- Ruff lint。
- mypy。
- pytest（单元与集成）。
- 前端 lint、typecheck、test、build。
- 依赖漏洞和密钥扫描。

M0 的 `.github/workflows/quality.yml` 分为后端、前端、Windows 桌面构建、依赖审查和密钥扫描任务。后端与前端依赖均使用锁文件，CI 安装时启用 frozen/locked 模式。

主分支或 Release Tag 增加：

- Tauri 多平台构建。
- 安装包冒烟。
- 数据库升级路径测试。
- SBOM、校验和和签名。

## 4. 发布 Gate

No-Go 条件：

- P0/P1 缺陷未关闭。
- 数据迁移不可恢复或未验证。
- 安装包无法在干净环境启动。
- 本地模式存在隐式云端请求。
- API Key 或敏感日志泄露。
- 核心闭环无端到端验证。
- 质量命令失败且无正式豁免记录。
