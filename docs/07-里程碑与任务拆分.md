# 里程碑与任务拆分

以下是个人开发的建议节奏，时间是估算，用于排优先级，不构成承诺。

## M0：工程骨架（2-4 天）

- 初始化 Git、uv、pnpm、Vue、Electron、FastAPI。
- 统一配置、日志、错误码、健康检查。
- SQLite + Alembic 首个迁移。
- 本地 API 启动令牌与桌面启动联动。
- CI 基础质量门禁。

完成标准：桌面应用可启动，显示 FastAPI 健康状态，测试与构建命令可执行。

## M1：工作空间（3-5 天）

- 创建/打开工作空间。（已完成）
- 最近项目和本地目录。（已完成）
- 用户设置、模型配置。（已完成）
- 数据备份与诊断页面。（已完成）

当前切片包含：系统目录选择、创建本地目录、名称/路径去重、最近访问排序、目录失效提示、SQLite
持久化、重命名、仅删除应用记录、桌面首页入口、主题设置、隐私安全的模型元数据配置和操作系统
凭据库接入，以及 SQLite 一致性备份、完整性检查和桌面维护页面。M1 功能范围已完成；备份恢复、
删除、自动调度及大型数据库异步 Worker 属于后续数据升级切片。

## M2：文档管线（5-8 天）

- 文档模型、版本和文件哈希。（已完成）
- Markdown/TXT 优先，随后 DOCX/PDF。（已完成）
- Worker 解析、进度、取消和错误恢复。（已完成）
- 文本预览和引用定位。（已完成）

当前切片包含系统文件选择、工作空间边界与文件大小检查、SHA-256 去重、文档版本、独立进程
解析、轮询进度、取消、超时、进程崩溃/重启恢复，以及 Markdown/TXT/DOCX/PDF 文本预览和稳定引用
片段。引用片段包含来源范围、全文字符偏移和稳定 ID，可供后续 AI 分析直接引用。PDF 当前只处理已有
文本层，不执行 OCR 或解密。系统选择器多选、桌面拖拽、最多 50 项的批量 API 和逐文件结果已完成，M2
文档管线至此完成。

## M3：AI 分析（7-10 天）

- Provider 抽象与 Ollama/OpenAI-compatible 实现。（已完成）
- 需求分析 Schema 和 Prompt。（五维结构化输出已完成）
- 分维度分析、汇总和稳定引用。（已完成）
- 云端数据逐次外发确认。（已完成）
- 待确认问题的人工确认与测试点转换。（已完成最小闭环）
- Qdrant Local 索引。

当前已交付切片包含：只允许回环地址的本地 Ollama Provider，以及仅接受 HTTPS、调用
`/chat/completions`、使用 Bearer 凭据与 strict JSON Schema 且禁止重定向的 OpenAI-compatible
Provider。分析输出固定为五维评分和带严重度/影响/建议/待确认问题的结构化发现，执行文档版本引用
归属校验，并在首次无效输出后修复重试一次。分析运行在独立 Worker 进程，覆盖排队、进度、成功、
失败、取消、超时、进程崩溃和应用重启恢复；本地与云端没有自动回退。

云端调用同时要求设置级同意和每次分析逐次确认。桌面确认框展示被冻结的 Provider、模型、完整 HTTPS
请求 endpoint（`base_url` 加 `/chat/completions`）、文档版本、全部稳定片段数和字符数，运行记录同时
冻结 `base_url`。POST 携带版本、Provider、模型、`base_url`、`input_chunk_count` 和
`input_character_count` 快照；后端发现任一项变化即拒绝并要求重新确认，以防止 TOCTOU。运行记录还
保存输入范围与云端确认时间。API Key 只由 Worker 子进程从操作系统凭据库读取，不进入 SQLite、
进程参数或日志；云端失败以安全错误返回。超过 200,000 字符的输入明确拒绝且不静默截断。

待确认问题可逐条接受或拒绝并保存说明；已接受问题可幂等转换为本地测试点草稿。测试点与来源问题
一对一，继续展示稳定原文引用，并支持标题、验证目标、类型、优先级、状态和自动化候选编辑。生成后
确认结论锁定，避免审计依据变化。已确认测试点可继续幂等生成一对一结构化用例，编辑前置条件、步骤与
期望、标签、自动化类型和状态，并批量确认或禁用。Qdrant Local 检索索引和模型多场景扩展仍属后续切片。

## M4：测试设计（5-8 天）

- 测试点生成和编辑。（单问题确认、幂等生成和编辑最小闭环已完成）
- 测试用例模型、步骤和批量确认。（本地确定性一对一草稿、编辑、批量确认/禁用已完成）
- 需求追踪矩阵。（稳定引用到确认、测试点、用例的实时派生矩阵及覆盖筛选已完成）
- 自动化候选规则。（确定性建议、生成继承、理由展示和现有草稿一键应用已完成）

## M5：接口执行（10-15 天）

- Job Manager 与 Worker 生命周期。（HTTP 单次任务的进度、取消、超时、崩溃和重启恢复已完成）
- HTTP Runner。（环境、普通/安全变量、模板、单次请求、脱敏结果、四类断言和安全重试已完成）
- WebSocket Runner。（环境复用、ws/wss 映射、有序多消息发送/接收、脱敏结果、可配置 Ping、最多一次
  受控重连、消息序列断言和完整 Worker 生命周期已完成；批量运行待后续）
- Protobuf 动态编解码。（单文件资产、结构摘要、冻结描述符、本地 JSON/Base64 编解码、非流式 RPC 的
  单次 HTTP 二进制执行、字段断言和 Worker 生命周期已完成；原生 gRPC、流式 RPC 与批量执行待后续）
- 实时日志、取消、超时、重跑。（五类长任务统一状态/进度推送、断线恢复、持久化安全事件刷新、取消、
  超时和 HTTP 冻结模板重跑已完成；跨任务批量运行和通用日志总线待后续）

## M6：报告与首发（7-10 天）

- 结果聚合、趋势和 AI 失败归因。（工作空间结果聚合、14 日 UTC 趋势、通过率/平均时长/慢执行，以及
  带规则 ID 的本地确定性初步归因已完成；模型辅助复核待后续）
- HTML/Markdown/JSON 导出。（同一只读快照的脱敏导出和 Electron 系统保存已完成）
- 打包、升级、数据迁移和安装冒烟。（PyInstaller onedir Sidecar、打包态自动迁移、用户数据目录、
  Electron 心跳回收、Forge 自包含候选目录、Squirrel 未签名安装器候选和 SHA-256 制品清单已完成；
  一次性 Windows runner 的制品校验、安装、首次启动、卸载和数据保留门禁已实现并观察通过；签名及
  携带上一候选的跨版本升级实测待后续）
- 用户手册、发布说明和已知问题。（Windows 内部候选发布说明和验证边界已完成；完整用户手册待后续）

当前报告切片不新增数据库表，不读取 keyring，也不把请求/响应正文或变量值带入报告。趋势只使用 UTC
完成时间，初步归因只使用稳定状态和错误码且不调用模型。后端只生成内容，实际路径由 Electron 主进程
通过系统保存对话框取得并校验。独立 Sidecar 已随 Forge package 分发，并在握手前自动迁移用户数据目录；
Squirrel 未签名安装器、CycloneDX SBOM、脱敏发布元数据与校验清单已生成并完成静态结构验证，可选 PFX
Secret 注入及签名/时间戳强制门禁、安装生命周期自动化也已接入 Windows CI。模型辅助复核、正式证书
实际签名和跨版本升级实测仍未完成；GitHub hosted Windows runner 的安装生命周期与完整用户手册已完成。
