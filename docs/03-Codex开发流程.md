# Codex App 开发流程

## 1. Codex 使用定位

Codex 负责：理解仓库、拆分任务、修改代码、运行命令、补测试、检查 diff 和生成文档。产品决策、验收口径、敏感操作审批和最终发布仍由开发者负责。

在当前桌面应用中，Codex 支持项目、多会话并行、Git worktree、Skills、计划任务、文件预览和变更审查。对本项目最有价值的是：

- `AGENTS.md` 固化项目规则。
- Worktree 隔离并行任务。
- Skills 固化“需求转计划、功能交付、发布门禁”等重复流程。
- 沙箱与审批控制命令、网络和工作区外文件访问。

## 2. 首次准备

1. 安装 ChatGPT 桌面应用并进入 Codex 模式。
2. 准备 Git、Python 3.12、uv、Node.js LTS、pnpm、Rust/Tauri 系统依赖。
3. 创建空 Git 仓库，将本文件包复制到仓库根目录。
4. 在 Codex 中打开仓库根目录。
5. 检查 `AGENTS.md` 和 `.codex/config.toml` 是否被识别。
6. 在桌面应用 Settings 中配置本地环境：
   - Setup script：安装后端和前端依赖。
   - Actions：后端启动、桌面开发、测试、质量检查。
7. 第一次只要求 Codex“读取文档并给出初始化计划”，不要直接一次生成全部产品。

## 3. 标准任务流程

### A. 需求对齐

使用 `requirement-to-plan` Skill 或 `templates/需求转任务提示词.md`。

Codex 输出必须包含：目标、非目标、用户流程、数据变化、接口变化、风险、验收标准、测试计划、文件影响清单。

开发者确认后再进入实现。

### B. 创建独立工作区

- 小型单文件修复：可在 Local 执行。
- 功能开发、重构、依赖升级：在独立 Worktree 执行。
- 多个互不依赖的任务可以并行开多个 Worktree。
- 同一数据库模型或同一核心文件的任务避免并行，减少合并冲突。

### C. 实施

Codex 按垂直切片交付：

1. 数据模型与迁移。
2. 领域/应用服务。
3. API 与 Schema。
4. 前端状态和页面。
5. 单元、集成和端到端测试。
6. 文档和变更说明。

每个切片应可运行、可验证，不接受“先写完全部代码再统一调试”。

### D. 验证

要求 Codex实际运行：

- 最小相关测试。
- Python lint、格式、类型检查。
- 前端 lint、类型检查、测试和构建。
- 必要时 Tauri 打包冒烟测试。
- 变更 diff 自审。

### E. 人工审查

在 Codex 变更面板逐文件检查：

- 是否超出需求范围。
- 是否破坏架构边界。
- 是否增加无必要依赖。
- 是否遗漏失败、取消、超时和恢复路径。
- 是否泄露密钥或完整请求数据。
- 测试是否真正验证行为，而不是只断言 Mock。

### F. 合并

- 保持一次提交只解决一个逻辑问题。
- 合并前更新主分支并重新运行关键测试。
- 记录数据库迁移和兼容性影响。
- 删除或保留 Worktree 按项目设置处理。

## 4. 开发阶段

### 阶段 0：仓库与工程骨架

产出：monorepo、FastAPI 健康接口、Vue/Tauri 窗口、SQLite 迁移、日志、配置和 CI。

### 阶段 1：本地工作空间

产出：项目创建/打开、应用目录、数据库初始化、最近项目、基础设置和健康诊断。

### 阶段 2：文档导入与解析

产出：文件导入、版本、解析 Worker、预览、错误恢复和文档引用定位。

### 阶段 3：AI 需求分析

产出：模型 Provider、Prompt、RAG、结构化评分、问题列表、引用和人工确认。

### 阶段 4：测试点和用例

产出：生成、编辑、批量确认、追踪需求引用和自动化候选标记。

### 阶段 5：接口执行

产出：HTTP、WebSocket、Protobuf Runner，任务状态机、实时日志、取消、超时和重跑。

### 阶段 6：报告与打包

产出：统计、失败归因、报告导出、数据备份、安装包、升级验证和发布说明。

## 5. Codex 对话管理

- 一个聊天只处理一个连贯目标。
- 需求变更造成方向分叉时使用 Fork 或新 Worktree。
- 聊天过长时先让 Codex总结“已确认决定、当前状态、待办和风险”，再继续。
- 重要架构决定写入 `docs/`，不要只存在聊天上下文。
- 重复三次以上的提示和修正，整理为 Skill 或 `AGENTS.md` 规则。

## 6. 每日节奏

开始开发：

1. 拉取主分支。
2. 查看上次未完成项和 CI。
3. 选一个可在半天到一天闭环的任务。
4. 让 Codex先给实施计划和验收映射。

结束开发：

1. 运行质量门禁。
2. 让 Codex自审 diff 和风险。
3. 更新任务状态与文档。
4. 提交可回滚的 Git commit。
5. 记录下一步的单一明确目标。
