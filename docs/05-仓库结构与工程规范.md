# 仓库结构与工程规范

## 1. 推荐 Monorepo

```text
.
├── AGENTS.md
├── README.md
├── pyproject.toml
├── uv.lock
├── package.json
├── pnpm-workspace.yaml
├── backend/
│   ├── app/
│   ├── migrations/
│   └── tests/
├── frontend/
│   ├── src/
│   └── src-tauri/
├── tests/
│   ├── integration/
│   └── e2e/
├── docs/
├── scripts/
├── .agents/skills/
├── .codex/
└── .github/workflows/
```

当前 M0 工程骨架遵循以上结构。根目录 `package.json` 只提供统一命令入口，Vue/Tauri 依赖和配置位于 `frontend/`；Python 项目和质量配置统一位于根目录 `pyproject.toml`。

## 2. Python 规范

- Python 3.12。
- 使用完整类型标注；公共函数不得省略返回类型。
- Pydantic Schema 与领域实体分离。
- I/O 接口优先 async；CPU/阻塞任务进入 Worker。
- 使用结构化日志，字段包含 `trace_id`、`job_id`、`workspace_id`。
- 错误使用项目异常类型并映射稳定错误码。
- 新依赖需说明必要性、许可证、体积和打包影响。

## 3. Vue/TypeScript 规范

- 使用 Composition API 和 `<script setup lang="ts">`。
- API 类型由统一 Schema 维护，不在页面重复定义。
- 状态按 feature 拆分 Pinia Store。
- 页面不直接访问 Tauri API，通过 `desktopBridge` 封装。
- 复杂业务状态由后端作为事实源，前端只维护展示状态。

## 4. Git 规范

分支建议：

- `main`：始终可构建。
- `feat/<scope>-<summary>`。
- `fix/<scope>-<summary>`。
- `chore/<summary>`。

提交示例：

- `feat(documents): add markdown import pipeline`
- `fix(jobs): recover cancelled worker state`
- `test(proto): cover unknown response fields`

一次提交包含功能代码、对应测试和必要文档，避免混入格式化全仓库等无关改动。

## 5. 配置

- `.env.example` 只包含示例键，不含真实值。
- 开发配置、运行时配置和用户设置分层。
- 用户模型 Key 存系统凭据库。
- 工作空间配置只保存相对路径或安全引用。

M0 开发环境约定：

- Tauri 通过参数数组调用项目 `.venv` 中的 Python，并负责 FastAPI 子进程生命周期。
- 桌面 FastAPI 绑定 `127.0.0.1` 随机端口，每次启动生成独立会话令牌；连接信息只通过父子进程管道与 Tauri IPC 传递。
- 独立 Web 调试仍可使用 `python -m backend.app.run`，默认绑定 `127.0.0.1:8765`，并可通过环境变量启用同一鉴权机制。
- Vue 只能通过 `frontend/src/api` 下的统一 Client 访问后端。
- `.env.example` 仅提供非敏感示例；本地 `.env` 不提交。
- 本地 SQLite 默认位于 `.local-data/`，该目录不提交。
