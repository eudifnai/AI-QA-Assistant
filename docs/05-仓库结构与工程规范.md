# 仓库结构与工程规范

## 1. 推荐 Monorepo

```text
.
├── AGENTS.md
├── README.md
├── pyproject.toml
├── uv.lock
├── package.json
├── pnpm-workspace.yaml
├── backend/
│   ├── app/
│   ├── migrations/
│   └── tests/
├── frontend/
│   ├── src/
│   ├── electron/
│   └── forge.config.cjs
├── tests/
│   ├── integration/
│   └── e2e/
├── docs/
├── scripts/
├── .agents/skills/
├── .codex/
└── .github/workflows/
```

当前 M0 工程骨架遵循以上结构。根目录 `package.json` 只提供统一命令入口，Vue/Electron 依赖和配置位于 `frontend/`；Python 项目和质量配置统一位于根目录 `pyproject.toml`。

## 2. Python 规范

- Python 3.12。
- 使用完整类型标注；公共函数不得省略返回类型。
- Pydantic Schema 与领域实体分离。
- I/O 接口优先 async；CPU/阻塞任务进入 Worker。
- 使用结构化日志，字段包含 `trace_id`、`job_id`、`workspace_id`。
- 错误使用项目异常类型并映射稳定错误码。
- 新依赖需说明必要性、许可证、体积和打包影响。

## 3. Vue/TypeScript 规范

- 使用 Composition API 和 `<script setup lang="ts">`。
- API 类型由统一 Schema 维护，不在页面重复定义。
- 状态按 feature 拆分 Pinia Store。
- 页面不直接访问 Electron 或 Node API，通过 context-isolated `desktopBridge` 封装。
- 复杂业务状态由后端作为事实源，前端只维护展示状态。

## 4. Git 规范

分支建议：

- `main`：始终可构建。
- `feat/<scope>-<summary>`。
- `fix/<scope>-<summary>`。
- `chore/<summary>`。

提交示例：

- `feat(documents): add markdown import pipeline`
- `fix(jobs): recover cancelled worker state`
- `test(proto): cover unknown response fields`

一次提交包含功能代码、对应测试和必要文档，避免混入格式化全仓库等无关改动。

## 5. 配置

- `.env.example` 只包含示例键，不含真实值。
- 开发配置、运行时配置和用户设置分层。
- 用户模型 Key 存系统凭据库。
- 工作空间配置只保存相对路径或安全引用。

M0 开发环境约定：

- Electron main 通过参数数组调用项目 `.venv` 中的 Python，并负责 FastAPI 子进程生命周期。
- 桌面 FastAPI 绑定 `127.0.0.1` 随机端口，每次启动生成独立会话令牌；连接信息只通过父子进程管道与受限 preload IPC 传递。
- 生产 renderer 使用 `app://ai-qa-assistant`，开发 renderer 只允许固定回环 Origin；两者均不暴露原始 `ipcRenderer`。
- 独立 Web 调试仍可使用 `python -m backend.app.run`，默认绑定 `127.0.0.1:8765`，并可通过环境变量启用同一鉴权机制。
- Vue 只能通过 `frontend/src/api` 下的统一 Client 访问后端。
- `.env.example` 仅提供非敏感示例；本地 `.env` 不提交。
- 本地 SQLite 默认位于 `.local-data/`，该目录不提交。

M1 工作空间约定：

- 创建接口只接受用户明确输入的绝对路径；相对路径返回 `WORKSPACE_PATH_INVALID`。
- 创建和打开都会检查目录存在、可写及最小可用空间，失败使用稳定工作空间错误码。
- 工作空间名称和规范化路径在 SQLite 中唯一，时间以 UTC 持久化。
- 重命名只更新显示名称及名称唯一键，不移动本地目录。
- 删除接口和桌面端“删除记录”只移除数据库记录；任何磁盘文件删除必须作为独立能力设计并再次确认。
- 数据库升级通过 `20260804_0002` Alembic 迁移创建 `workspaces` 表；更新代码后需执行
  `uv run alembic upgrade head`。

M1 用户设置约定：

- `20260809_0003` 迁移创建单例 `app_settings` 表，表中不得出现 API Key、Token、密码或凭据值列。
- 非敏感设置接口使用 `extra="forbid"` 拒绝额外字段；模型密钥只能通过单用途凭据接口进入
  `KeyringCredentialStore`，响应不得包含密钥。
- 系统凭据访问依赖 `keyring>=25.7,<26`；业务和 API 层不得直接导入或调用具体 keyring SDK。
- 本地模型地址限制为回环主机；云端基础地址必须使用 HTTPS，且保存前要求显式数据外发同意。
- 保存设置不代表连接模型或授权数据外发；真实调用仍需 Provider 层和逐次外发确认。
- 前端凭据输入只保存在组件瞬时内存中，请求结束后必须清空；Pinia 不得保存密钥值。
- 系统目录选择由 Electron main 调用原生 dialog，renderer 只能通过无参数的单用途桥请求选择结果。

M1 备份与诊断约定：

- 备份必须使用 SQLite Online Backup API，不得在数据库打开期间直接复制主数据库文件。
- 备份先写入唯一临时文件，`integrity_check` 返回 `ok` 后才可发布为 `.db`；异常时清理临时文件。
- 备份文件只允许位于业务数据库同级的 `backups/` 目录，命名使用应用固定前缀和 UTC 时间戳。
- 备份范围不得包含工作空间原文件、系统凭据、缓存或向量索引；当前 API 不提供恢复与删除。
- 维护 API 仍使用统一认证与错误响应，Vue 只能经 `frontend/src/api/maintenance.ts` 访问。

M2 文档导入约定：

- Electron 文件选择桥不接受 renderer 传入路径或筛选器，只返回用户明确选择的
  `.md/.txt/.docx/.pdf`；多选最多由 API 接收 50 项。拖拽不得使用已移除的 `File.path`，只能在 preload
  通过 Electron `webUtils.getPathForFile` 解析 Web `File` 对应的磁盘路径。
- 后端仅接受绝对路径，并在跟随符号链接后的真实路径上执行工作空间边界检查；数据库只保存相对路径。
- 默认文件上限由 `AI_QA_DOCUMENT_MAX_BYTES` 配置（10 MiB），解析超时由
  `AI_QA_DOCUMENT_PARSE_TIMEOUT_SECONDS` 配置（60 秒）。
- SHA-256 以分块方式计算；Worker 读取前必须重新校验大小和哈希，防止排队期间文件被替换。
- 解析任务必须运行于 `spawn` Worker，FastAPI 路由只创建任务和查询状态；取消、超时、异常退出与
  重启恢复必须进入稳定终态。
- `20260810_0004` 迁移创建 `documents`、`document_versions` 和 `document_jobs`；升级前先备份 SQLite。
- `20260811_0005` 迁移创建 `document_chunks`，以 `(version_id, ordinal)` 保证版本内顺序唯一，并将已有
  成功版本回填为单个全文引用片段。新解析必须在完成任务的同一事务中替换该版本的引用片段。
- DOCX 解析依赖 `python-docx>=1.2,<2`，PDF 解析依赖 `pypdf>=6.14,<7`；具体 SDK 只允许在
  `infrastructure/document_parsers.py` 中使用，Worker 和应用层依赖统一解析接口。
- PDF 只解析未加密文件的已有文本层；图片扫描件返回 `DOCUMENT_TEXT_EMPTY`，不得隐式调用 OCR 或云服务。
- Vue 通过统一 API Client 调用 `GET /api/workspaces/{workspace_id}/documents/{document_id}/chunks`；不得从
  `parsed_text` 临时计算引用 ID。引用 ID、来源范围和字符偏移由后端持久化结果提供。
- 批量导入使用 `POST /api/workspaces/{workspace_id}/documents/batch`，返回 HTTP 207 和保持输入顺序的
  `accepted/rejected` 结果。业务错误逐项返回稳定错误码；工作空间不存在或意外异常仍返回顶层错误。

M5 HTTP 执行约定：

- `20260815_0010` 迁移创建 `http_environments` 与 `http_executions`；`20260816_0011` 增加断言快照、
  断言结果和 `http_execution_events`。升级前先通过维护页备份 SQLite。
- 环境 Base URL 只接受无 userinfo、query 和 fragment 的 HTTP/HTTPS 地址；请求路径必须是以单个 `/`
  开头的相对路径，Header 名称和值需防止 CR/LF 注入。
- 普通变量以字符串映射存 SQLite；安全变量只在 SQLite 保存名称，值使用
  `KeyringHttpSecretStore` 按环境 ID 和变量名隔离。前端安全变量值只存在组件瞬时内存并在请求后清空。
- 请求模板只保存 `{{NAME}}` 与 `{{secret.NAME}}` 引用。Worker 子进程读取并展开安全变量，展开结果不得
  写入 SQLite、进程参数或日志。环境更新不会改写已有运行快照。
- 单次 HTTP 请求必须运行在 `spawn` Worker；默认 Supervisor 总超时由
  `AI_QA_HTTP_EXECUTION_TIMEOUT_SECONDS=190` 配置。当前请求超时为 1-60 秒、请求体上限 1 MiB、响应体
  上限 2 MiB；重定向不得自动跟随。
- 状态码、响应头等值、正文包含和 JSON 路径等值断言最多 20 条。断言失败保留脱敏响应并标记 `failed`；
  4xx/5xx 本身是成功收到的响应，不等同于 Runner 故障。GET/HEAD/OPTIONS 可对超时或服务不可用执行
  最多 3 次尝试，其他方法固定一次，鉴权、限流、断言失败均不自动重试。
- 运行事件按序持久化稳定代码、级别、尝试次数和静态中文消息，不保存展开请求、响应正文或凭据。终态
  运行可按冻结模板创建新运行；原环境已删除时拒绝重跑，避免隐式选择其他目标。

M5 WebSocket 执行约定：

- `20260816_0012` 创建 WebSocket 运行与有序事件表，复用 `http_environments` 及其 keyring 安全变量；
  运行只冻结环境、变量名称和请求模板，不保存安全变量值。
- HTTP/HTTPS Base URL 分别映射为 ws/wss；请求路径不得替换 Origin 或包含 fragment。连接必须禁用系统
  代理，单条发送消息限制 1 MiB、单条接收消息限制 2 MiB。
- WebSocket 长任务必须运行在 `spawn` Worker，默认 Supervisor 总超时由
  `AI_QA_WEBSOCKET_EXECUTION_TIMEOUT_SECONDS=130` 配置；任务覆盖取消、超时、进程崩溃和重启恢复。
- 当前切片只发送一条文本消息并接收一条文本或二进制消息。自动重连、可配置心跳、多消息序列断言和
  重跑不得伪装为已交付能力。
