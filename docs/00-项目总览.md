# 项目总览

## 1. 项目名称

暂定：**AI QA Assistant**。

## 2. 产品定位

一款运行在测试工程师电脑上的本地 AI 助手，通过读取需求文档、原型、Proto 协议和测试资产，辅助完成需求评审、测试设计、自动化执行和报告分析。

它不是首期面向团队协作的 SaaS，也不承担完整缺陷管理、组织权限和跨团队流程审批。MVP 首先解决个人 QA 高频、重复、容易遗漏的工作。

## 3. 核心用户

- 熟悉 Python 的测试工程师。
- 需要测试 Unity 游戏 APK/IPA 的 QA。
- 需要处理 HTTP、WebSocket、Protobuf 协议的接口测试人员。
- 希望在本地使用 AI 分析敏感需求和代码资产的个人开发者。

## 4. 核心价值

1. **本地优先**：需求、Proto、日志和报告默认存储在本机。
2. **从需求到执行**：避免 AI 只生成文本，结果可继续转为用例和可执行任务。
3. **结构化可审计**：分析结论、测试点和失败归因使用固定 Schema。
4. **技术统一**：后端、AI 和测试执行使用 Python，降低个人维护成本。
5. **渐进扩展**：先完成 HTTP/WebSocket/Protobuf，再扩展 Web、Android、iOS 和 Unity。

## 5. 产品主流程

1. 创建或打开本地工作空间。
2. 导入需求文档、Figma 导出信息、截图、Proto 和现有用例。
3. 选择模型和分析模板。
4. 生成需求评分、风险项、待确认问题和改进建议。
5. 确认测试范围，生成测试点和结构化用例。
6. 将可自动化用例转换为测试任务。
7. 执行并实时查看日志、进度和结果。
8. AI 汇总失败原因、疑似产品缺陷、环境问题和脚本问题。
9. 导出 Markdown、HTML 或 JSON 报告。

## 6. 产品原则

- 默认不上传用户数据。
- AI 输出必须可追溯到输入文档或明确标记为推断。
- 自动执行前展示目标环境、请求参数和潜在副作用。
- 所有长任务可取消、可恢复、可定位失败。
- MVP 优先纵向打通闭环，不追求功能数量。
