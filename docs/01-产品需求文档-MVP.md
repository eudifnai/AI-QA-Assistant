# 产品需求文档（MVP）

## 1. MVP 目标

在单机环境内完成一条可用闭环：

`需求导入 → AI 需求分析 → 测试用例生成 → HTTP/WebSocket/Protobuf 执行 → 报告分析`

## 2. 功能范围

### 2.1 工作空间

- 创建、打开、重命名和删除本地工作空间。
- 最近项目列表。
- 工作空间路径选择和可用空间检查。
- 项目配置、模型配置、环境变量引用。

验收标准：重新启动应用后可恢复项目、文档、用例和执行历史。

当前已交付的 M1 切片支持系统目录选择、创建、最近列表、打开、重命名、仅删除应用记录和
SQLite 持久化恢复。删除记录不会删除用户本地目录或文件。用户设置已支持主题以及本地 Ollama / 云端
OpenAI-compatible 模型配置，并可将 API Key 写入、查询状态或从操作系统凭据库清除。密钥不会
写入 SQLite 或返回前端；当前只在用户主动发起需求分析并完成适用确认后连接已展示的模型服务。
维护页面已支持查看本机运行与数据库诊断信息，并手动创建 SQLite 一致性备份。备份不包含工作空间
原文件和系统凭据；恢复、删除及
自动备份不属于当前切片。

### 2.2 文档导入

首期支持：Markdown、TXT、DOCX、PDF、HTML、PNG/JPG、`.proto`。

- 拖拽或文件选择导入。
- 文件哈希去重。
- 解析状态和错误提示。
- 原文预览与解析文本预览。
- 文档版本和重新解析。

验收标准：损坏文件不会导致应用退出；解析错误可定位到文件和阶段。

当前 M2 切片支持从系统文件选择器导入工作空间内的 Markdown、TXT、DOCX 和 PDF，按工作空间
使用 SHA-256 去重并保存文档版本。解析在独立 Worker 进程执行，页面显示进度、失败原因、取消
入口和文本预览；应用重启会将遗留的排队/运行任务恢复为可审计的错误终态。DOCX 提取正文段落
和表格，PDF 按页提取已有文本层。解析成功后按文本行段、DOCX 块或 PDF 页保存稳定引用片段，并在预览中
展示来源范围和引用 ID；升级前已解析的文档回填为全文引用片段。当前不执行 OCR，也不支持加密 PDF、
文件夹递归导入或文档删除。系统选择器和桌面拖拽均支持单次最多 50 个文件；批量导入逐文件返回成功或
稳定业务错误，单个文件失败不会阻断同批其他文件。

### 2.3 需求 AI 分析

分析维度：完整性、一致性、清晰度、可测性、可行性。

输出：

- 总体评分及分项评分。
- 优点。
- High/Medium/Low 风险问题。
- 每个问题的原文依据、影响、建议和待确认问题。
- 建议补充的状态机、异常流、权限、接口契约和验收标准。

验收标准：输出通过固定 JSON Schema 校验；每个问题可回到引用片段。

当前 M3 已支持本地 Ollama 和 OpenAI-compatible 云端五维分析、总体/分项评分，以及带严重度、影响、
建议、待确认问题和稳定原文引用的结构化发现。云端模式要求先保存设置级数据外发同意，并在每次分析前
逐次确认被冻结的 Provider、模型、完整 HTTPS 请求 endpoint（`base_url` 加 `/chat/completions`）、
文档版本、全部稳定片段数和字符数；运行记录同时冻结 `base_url`。创建任务时提交版本、Provider、模型、
`base_url`、`input_chunk_count` 和 `input_character_count` 快照，后端在其中任何一项变化时拒绝执行
并要求重新确认。API Key 只保存在操作系统凭据
库并由 Worker 子进程执行时读取，不进入 SQLite、进程参数或日志。独立 Worker 支持进度、取消、超时、
崩溃识别与重启恢复，且本地/云端之间没有自动回退。输出经过 Pydantic Schema 和引用归属校验，首次
失败修复重试一次；输入超过 200,000 字符会明确拒绝且不会静默截断。待确认问题现可逐条接受或拒绝并
保存确认说明；已接受的问题可在本地幂等转换为带来源问题 ID 和稳定原文引用的测试点草稿，已确认
测试点还可幂等转换为结构化测试用例草稿。两段转换都不会再次调用模型。Qdrant Local 检索索引和
模型驱动的多场景扩展尚未交付。

### 2.4 测试设计

- 从确认后的需求范围生成测试点。
- 测试点转为结构化测试用例。
- 支持正向、异常、边界、状态流转、权限、兼容和性能测试类型。
- 人工编辑、批量确认、禁用和标记自动化候选。

当前测试设计切片已支持逐条人工确认，以及测试点标题、验证目标、测试类型、P0-P3 优先级、状态和
自动化候选标记的编辑。每个来源问题最多生成一个测试点；生成后确认结论锁定。已确认测试点可生成
一对一结构化用例草稿，编辑标题、前置条件、步骤与期望、优先级、标签、自动化类型和状态，并支持
多选批量确认或禁用；生成后来源测试点锁定。当前运行还会实时派生需求追踪矩阵，按分析问题展示
稳定原文引用、人工结论、测试点、测试用例和统一覆盖状态，并支持覆盖汇总及状态筛选。模型驱动的
多场景扩展仍待后续切片。

自动化候选规则在本地按测试类型确定性执行：异常、边界、状态、权限和性能建议 API 自动化；正向与
兼容性建议先人工评审。每条建议展示稳定规则编号与原因，新生成对象自动继承，已有草稿需人工点击
应用且可继续覆盖最终类型。规则不读取模型凭据、不调用模型，也不代表用例已经具备可执行脚本。

测试用例字段：标题、前置条件、步骤、期望、优先级、标签、需求引用、自动化类型。

### 2.5 接口资产

- 导入和管理 `.proto` 文件。
- 解析 package、service、message、enum 和字段。
- 配置 HTTP、WebSocket 环境。
- 支持变量、密钥引用和数据集。
- 请求/响应模板和字段断言。

### 2.6 测试执行

首期 Runner：

- HTTP：请求、重试、超时、JSON/文本/二进制响应、断言。
- WebSocket：连接、发送、接收、心跳、超时、消息序列断言。
- Protobuf：动态消息构造、编码、解码和字段断言。

执行能力：队列、实时日志、进度、取消、超时、重跑失败、单用例调试。

当前 M5 HTTP 切片已支持工作空间级 HTTP/HTTPS 环境、普通变量和操作系统凭据库安全变量。请求模板使用
`{{NAME}}` 与 `{{secret.NAME}}` 引用变量，可执行 GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS 单次请求。
执行进入独立 Worker，页面通过统一任务事件流接收进度并支持取消，同时保留轮询恢复；请求超时限制为 1-60 秒，Supervisor 同时处理超时、
进程崩溃和应用重启后的遗留任务。结果记录状态码、耗时、脱敏响应头及最多 2 MiB 的 UTF-8 文本或
Base64 二进制响应，且不自动跟随重定向。安全变量值不进入 SQLite、执行模板、Worker 进程参数或前端
Store。当前还支持状态码、响应头、正文包含、JSON 路径等值断言；GET/HEAD/OPTIONS 仅对超时或服务
不可用执行最多 3 次尝试；结构化安全事件可随任务更新刷新查看，终态运行可按冻结模板重跑。数据集和
批量运行尚未包含在该 HTTP 接口切片。

当前 WebSocket 切片复用 HTTP/HTTPS 环境并映射为 ws/wss，支持普通/安全变量模板化路径、握手头，以及
最多 10 条有序文本发送消息和 20 条有序文本/Base64 二进制接收消息。可配置 5-60 秒 Ping 心跳、最多
一次仅针对传输超时或不可用的自动重连，以及编码、文本等值/包含、JSON 路径严格等值断言。执行进入
独立 Worker，支持实时任务推送、轮询恢复、取消、Supervisor 总超时、进程崩溃和重启恢复；响应与有序事件落库前脱敏。
自动重连会重放完整发送序列，界面明确提示其重复副作用风险。批量执行和历史运行重跑
留到后续切片。

当前 Protobuf 支持导入工作空间内最大 1 MiB 的单个 `.proto`，解析 package、service/RPC、message、
enum 和字段，冻结文件 SHA-256 与 FileDescriptorSet，并在本机按指定 message 完成 JSON ↔ Protobuf
Base64 动态编解码。执行页可复用 HTTP 环境和安全变量，选择非流式 RPC，将请求 JSON 编码后通过独立
Worker 执行单次 `application/x-protobuf` HTTP POST，解码最多 2 MiB 的响应并执行严格类型字段等值断言；
支持实时任务推送、轮询恢复、取消、超时、崩溃及重启恢复。仅允许 `google/protobuf` 内置 import；
本地多文件 import、原生 gRPC、流式 RPC 和批量执行尚未包含。

当前统一任务事件流覆盖文档解析、AI 分析和三类接口执行。事件只携带工作空间、任务类型、任务 ID、
统一状态、进度和生命周期时间戳；详细结果及脱敏安全事件仍由原有作用域 API 读取。重新连接或检测到序号缺口
时前端主动刷新当前任务，避免把瞬时连接中断误当成任务失败。

### 2.7 报告

- 总数、通过、失败、错误、取消、超时。
- 通过率、执行时长和慢用例。
- 请求/响应摘要和脱敏日志。
- AI 失败归因：产品问题、环境问题、数据问题、脚本问题、未知。
- 导出 Markdown、HTML 和 JSON。

当前 M6 已按工作空间即时聚合 HTTP、WebSocket 和 Protobuf 执行历史，展示总数、终态分布、最近
14 个 UTC 自然日趋势、通过率、平均时长和慢执行，并补充分析评分/问题及测试点/用例确认摘要。通过率
分母只包含通过、失败、错误和超时，不包含取消或进行中任务。失败执行先按稳定状态与错误码确定性归为
产品、环境、数据、脚本或未知，并展示规则 ID 和理由；该结果不调用模型，是可审计的初步归因，未知项
需人工复核，模型辅助归因仍属于后续切片。JSON、Markdown 和 HTML 由后端按同一快照确定性生成，经
再次脱敏后交给 Electron 系统保存对话框；不导出请求/响应正文、凭据值、普通变量值或 keyring 内容。

### 2.8 模型与知识库

- Ollama 本地模型。
- OpenAI-compatible Provider。
- 模型能力和隐私提示。
- 项目级知识库索引与重建。
- 禁止本地模式自动回退到云端。

## 3. 非目标

MVP 不实现：

- 多租户、组织架构、复杂 RBAC。
- 云端协作和实时多人编辑。
- 完整缺陷管理系统。
- 分布式设备农场。
- iOS 真机规模化调度。
- 全自动 Agent 自主修改生产环境。

## 4. 关键非功能要求

- 冷启动目标：普通开发机 5 秒内出现主窗口；后台服务异常需要可见提示。
- 任务可靠性：应用 UI 重启后可查看历史任务；运行中任务需明确标记是否已中断。
- 安全：本地 API 只监听 Loopback，使用启动令牌；敏感字段默认脱敏。
- 可维护性：领域规则和外部适配器隔离，核心模块单元测试覆盖率目标 80%。
- 可升级性：数据库升级由 Alembic 管理，失败可回滚安装版本并保留数据备份。
