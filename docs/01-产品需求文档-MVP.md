# 产品需求文档（MVP）

## 1. MVP 目标

在单机环境内完成一条可用闭环：

`需求导入 → AI 需求分析 → 测试用例生成 → HTTP/WebSocket/Protobuf 执行 → 报告分析`

## 2. 功能范围

### 2.1 工作空间

- 创建、打开、重命名和删除本地工作空间。
- 最近项目列表。
- 工作空间路径选择和可用空间检查。
- 项目配置、模型配置、环境变量引用。

验收标准：重新启动应用后可恢复项目、文档、用例和执行历史。

### 2.2 文档导入

首期支持：Markdown、TXT、DOCX、PDF、HTML、PNG/JPG、`.proto`。

- 拖拽或文件选择导入。
- 文件哈希去重。
- 解析状态和错误提示。
- 原文预览与解析文本预览。
- 文档版本和重新解析。

验收标准：损坏文件不会导致应用退出；解析错误可定位到文件和阶段。

### 2.3 需求 AI 分析

分析维度：完整性、一致性、清晰度、可测性、可行性。

输出：

- 总体评分及分项评分。
- 优点。
- High/Medium/Low 风险问题。
- 每个问题的原文依据、影响、建议和待确认问题。
- 建议补充的状态机、异常流、权限、接口契约和验收标准。

验收标准：输出通过固定 JSON Schema 校验；每个问题可回到引用片段。

### 2.4 测试设计

- 从确认后的需求范围生成测试点。
- 测试点转为结构化测试用例。
- 支持正向、异常、边界、状态流转、权限、兼容和性能测试类型。
- 人工编辑、批量确认、禁用和标记自动化候选。

测试用例字段：标题、前置条件、步骤、期望、优先级、标签、需求引用、自动化类型。

### 2.5 接口资产

- 导入和管理 `.proto` 文件。
- 解析 package、service、message、enum 和字段。
- 配置 HTTP、WebSocket 环境。
- 支持变量、密钥引用和数据集。
- 请求/响应模板和字段断言。

### 2.6 测试执行

首期 Runner：

- HTTP：请求、重试、超时、JSON/文本/二进制响应、断言。
- WebSocket：连接、发送、接收、心跳、超时、消息序列断言。
- Protobuf：动态消息构造、编码、解码和字段断言。

执行能力：队列、实时日志、进度、取消、超时、重跑失败、单用例调试。

### 2.7 报告

- 总数、通过、失败、错误、取消、超时。
- 通过率、执行时长和慢用例。
- 请求/响应摘要和脱敏日志。
- AI 失败归因：产品问题、环境问题、数据问题、脚本问题、未知。
- 导出 Markdown、HTML 和 JSON。

### 2.8 模型与知识库

- Ollama 本地模型。
- OpenAI-compatible Provider。
- 模型能力和隐私提示。
- 项目级知识库索引与重建。
- 禁止本地模式自动回退到云端。

## 3. 非目标

MVP 不实现：

- 多租户、组织架构、复杂 RBAC。
- 云端协作和实时多人编辑。
- 完整缺陷管理系统。
- 分布式设备农场。
- iOS 真机规模化调度。
- 全自动 Agent 自主修改生产环境。

## 4. 关键非功能要求

- 冷启动目标：普通开发机 5 秒内出现主窗口；后台服务异常需要可见提示。
- 任务可靠性：应用 UI 重启后可查看历史任务；运行中任务需明确标记是否已中断。
- 安全：本地 API 只监听 Loopback，使用启动令牌；敏感字段默认脱敏。
- 可维护性：领域规则和外部适配器隔离，核心模块单元测试覆盖率目标 80%。
- 可升级性：数据库升级由 Alembic 管理，失败可回滚安装版本并保留数据备份。
