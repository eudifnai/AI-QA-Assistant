# 技术架构设计

## 1. 总体架构

```text
Electron Desktop
└── Vue 3 / TypeScript / Element Plus
        │ HTTP + WebSocket (127.0.0.1 + session token)
        ▼
FastAPI Local Service
├── Workspace / Documents / Cases / Reports API
├── AI Orchestration
├── Job Manager
└── Local Tool Gateway
        │
        ├── SQLite + SQLModel + Alembic
        ├── Qdrant Local + embedding model
        ├── Ollama / OpenAI-compatible model
        └── Python Worker Processes
             ├── HTTP Runner
             ├── WebSocket Runner
             ├── Protobuf Runner
             ├── Playwright Runner（后续）
             └── Appium / Unity Adapter（后续）
```

## 2. 进程模型

### 桌面主进程

负责窗口、托盘、文件选择、应用目录、更新和 FastAPI Sidecar 生命周期。

### FastAPI API 进程

负责短请求、数据查询、任务创建、WebSocket 推送和健康检查。禁止在该进程直接执行长时间 LLM 推理或自动化测试。

### Worker 进程

负责文档解析、向量化、LLM 分析、测试执行和报告生成。每个任务记录 PID、心跳、进度和取消标记。

## 3. 后端分层

## 5. 数据模型

核心实体：

- `Workspace`：本地工作空间。
- `Project`：产品或测试项目。
- `Document` / `DocumentVersion` / `DocumentChunk`。
- `AnalysisRun` / `AnalysisIssue` / `SourceCitation`。
- `TestPoint` / `TestCase` / `TestStep`。
- `Environment` / `SecretReference` / `ProtoAsset`。
- `TestSuite` / `Execution` / `CaseResult` / `Artifact`。
- `ModelProfile` / `Conversation` / `Message`。
- `Job` / `JobEvent`。

所有实体使用 UUID；时间统一存 UTC，UI 按本地时区显示。

`ProtoAsset` 保存工作空间相对路径、SHA-256、大小和冻结 FileDescriptorSet。`.proto` 由
`grpcio-tools` 通过无 Shell 的参数数组在受限子进程中编译；首切片拒绝本地多文件 import，只额外开放
随工具安装且版本固定的 `google/protobuf` include。动态消息类只从冻结描述符构造，不导入或执行生成的
Python 代码。

`ProtobufExecution` 冻结环境、资产 SHA-256、FileDescriptorSet、非流式 Service/RPC、请求 JSON、字段
断言和模板。独立 `spawn` Worker 从 SQLite 读取快照，在子进程内从 keyring 读取安全变量并展开路径与
请求头，将动态编码结果以 `application/x-protobuf` HTTP POST 发送；禁用代理与重定向。最多 2 MiB 的
响应使用冻结描述符解码，字符串字段和响应头脱敏后持久化，再按 JSON 字段路径做严格类型等值断言。
Supervisor 负责取消、总超时、非零退出和重启恢复；本切片不实现原生 gRPC 或流式 RPC。

### 工作空间切片

- `workspaces` 表保存 UUID、显示名称、规范化绝对路径、创建时间和最近打开时间。
- 名称与路径分别通过大小写折叠键保持唯一，避免 Windows 路径或名称大小写差异造成重复。
- `GET /api/workspaces` 按最近打开时间返回列表。
- `POST /api/workspaces` 创建并记录本地目录。
- `POST /api/workspaces/{workspace_id}/open` 重新校验目录可用性并更新最近打开时间。
- `PATCH /api/workspaces/{workspace_id}` 更新显示名称，并保持大小写折叠后的名称唯一。
- `DELETE /api/workspaces/{workspace_id}` 仅删除 SQLite 记录并返回已删除项，不触碰工作空间目录。
- 路径创建、可写性和磁盘空间检查由 `LocalWorkspaceStorage` 适配器负责，应用服务不直接绑定文件系统实现。

### 用户设置切片

- `app_settings` 使用主键固定为 `1` 的单例记录，保存主题、模型模式、Provider、模型名、基础 URL、
  云端数据同意状态和更新时间。
- `GET /api/settings` 返回当前设置；首次读取时写入隐私安全的本地 Ollama 默认值。
- `PUT /api/settings` 全量更新非敏感设置，并拒绝未声明字段，因此 `api_key`、Token 或密码不能进入 SQLite。
- `GET/PUT/DELETE /api/settings/model-credential` 分别查询配置状态、写入和清除系统凭据；响应只有
  `configured`，不返回密钥或凭据标识。
- `KeyringCredentialStore` 使用固定 service/account 调用 Python `keyring`；应用层只依赖
  `CredentialStore` 协议，并将凭据库故障映射为 `CREDENTIAL_STORE_UNAVAILABLE`。
- 本地模式仅允许 Ollama 和回环 URL；云端模式仅允许 OpenAI-compatible、HTTPS URL 和显式数据外发同意。
- 需求分析支持已配置的本地 Ollama 与 OpenAI-compatible 云端服务。云端模式除设置级同意外，每次
  分析都必须再次确认被冻结的 Provider、模型、完整 HTTPS 请求 endpoint（`base_url` 加
  `/chat/completions`）、文档版本和完整输入范围；运行记录同时冻结 `base_url`。本地与云端
  之间不会自动回退。

### 备份与诊断切片

- `GET /api/diagnostics` 聚合应用/Python/平台版本、固定回环监听地址以及 SQLite 路径、大小、
  `quick_check` 结果、Alembic 版本、工作空间数和备份数。
- `GET /api/backups` 列出数据库同级 `backups/` 目录内由应用创建的备份；
  `POST /api/backups` 使用 SQLite Online Backup API 生成唯一命名的临时副本，执行
  `integrity_check` 后再原子替换为 `.db` 文件。
- 应用层只依赖 `MaintenanceStorage` 协议，SQLite 文件、备份目录和完整性检查由
  `SqliteMaintenanceStorage` 封装；存储故障统一映射为 `BACKUP_UNAVAILABLE`。
- 当前备份范围仅为业务 SQLite，不复制工作空间目录，不读取或导出 keyring 凭据。恢复、删除、
  定时备份及面向大型数据库的异步 Job/Worker 流程留到数据升级切片。

### 文档解析管线切片

- `documents` 保存工作空间内相对路径；`document_versions` 保存版本号、SHA-256、大小、解析文本和
  状态；`document_jobs` 保存进度、PID、错误码以及开始/结束时间。
- `POST /api/workspaces/{workspace_id}/documents` 只接收系统选择器返回的本机绝对路径；
  `LocalDocumentFiles` 使用 `resolve` 验证真实路径位于工作空间内，限制扩展名和大小后分块计算哈希。
- 同一路径内容变化会生成下一版本；同一工作空间已有相同 SHA-256 时返回
  `DOCUMENT_DUPLICATE`，避免重复解析。
- API 创建 `queued` 记录后立即返回 `202`；`DocumentParseWorkerManager` 使用 Python `spawn`
  启动独立进程，子进程重新验证文件边界、大小和哈希，再以 UTF-8 解析并写回结果。
- 主进程监督 Worker 超时和非零退出，支持精确取消；重启后将遗留的 `queued/running` 任务标记为
  `DOCUMENT_WORKER_INTERRUPTED`，所有终态更新保持幂等。
- `GET /api/workspaces/{workspace_id}/documents` 和详情接口返回最新版、任务状态和文本预览；统一任务
  WebSocket 通知状态或进度变化后由 Vue 刷新作用域详情，750ms 轮询保留为断线恢复兜底。
- `DocumentTextParser` 作为解析适配器按后缀分派：Markdown/TXT 使用严格 UTF-8，DOCX 通过
  `python-docx` 按正文顺序提取段落和表格，PDF 通过 `pypdf` 按页提取文本并插入页边界标记。
- 解析器同时返回全文和确定性 `DocumentChunk` 草稿：Markdown/TXT 按非空行段，DOCX 按正文块，PDF
  按有文本的页面分段。Worker 在完成任务的同一事务中写入版本内序号、来源范围、全文字符偏移和基于
  `version_id + ordinal` 生成的稳定 UUID；引用查询使用独立端点，避免文档列表进一步膨胀。
- Electron 多选桥只返回系统选择器明确选中的路径；拖拽文件由 preload 使用 `webUtils.getPathForFile`
  解析磁盘路径，不读取 renderer 自定义的路径字段。Vue 将最多 50 个路径提交到批量端点，应用服务顺序
  复用单文件校验与任务创建，并把预期业务失败转换为逐项结果；意外异常仍由统一错误中间件处理。
- 二进制解析设置 2,000 页、10,000 个 DOCX ZIP 条目、100 MiB DOCX 解压总量、100,000 个
  DOCX 块、100,000 个引用片段和 5,000,000 字符上限；损坏容器、加密 PDF、无文本层和超限均进入稳定 `failed`
  终态。当前不启用 PDF 解密、宏或 OCR。

## 6. 任务状态机

```text
pending → queued → running → passed
                    ├──────→ failed
                    ├──────→ error
                    ├──────→ cancelled
                    └──────→ timeout
```

终态不可直接回到运行态；重跑创建新的 Execution，并通过 `retry_of_id` 关联原任务。

## 7. AI 架构

业务层依赖抽象接口：

- `ChatModelProvider`
- `EmbeddingProvider`
- `StructuredOutputParser`
- `PromptTemplateRepository`
- `RetrievalService`

需求分析采用“切片检索 + 分维度分析 + 汇总去重 + Schema 校验”的确定性流程，不让单个自由 Agent 无限制循环。

当前 M3 分析使用已解析文档版本的全部稳定 `DocumentChunk`，总输入限制为 200,000 字符；
超限直接返回 `ANALYSIS_INPUT_TOO_LARGE`，不会静默截断。Qdrant Local 检索索引将在后续切片替换
全量输入策略。

- `analysis_runs` 冻结本次文档版本、Provider、模型和 `base_url`，并记录 PID、进度与统一任务终态；
  `20260812_0007` 迁移增加 `input_chunk_count`、`input_character_count` 和
  `cloud_data_confirmed_at`，使云端确认时的数据范围及确认时间可审计。
- `analysis_scores` 固定保存完整性、一致性、清晰度、可测性和可行性五个评分。
- `analysis_issues` 保存严重度、描述、影响、建议和待确认问题；`analysis_citations` 只允许关联本次
  文档版本已有的稳定引用片段。
- `20260814_0008` 增加 `analysis_issue_reviews` 和 `test_points`。确认记录与分析问题一对一；测试点
  通过唯一 `source_issue_id` 与来源问题一对一，重复生成返回已有记录。测试点保留运行 ID、标题、
  验证目标、类型、优先级、状态、自动化候选和时间戳，来源引用由分析问题链路追溯。
- `20260814_0009` 增加 `test_cases` 和规范化的 `test_case_steps`。测试用例通过唯一
  `source_test_point_id` 与来源测试点一对一；步骤按 `case_id + ordinal` 唯一并随用例级联删除。
- `POST /api/workspaces/{workspace_id}/documents/{document_id}/analysis-runs` 接收预期文档版本、
  Provider、模型、`base_url`、`input_chunk_count`、`input_character_count` 和逐次云端确认状态；
  应用服务将快照与当前文档、设置及重新计算的输入范围比较，任一项变化都拒绝任务并要求重新确认，
  防止确认和执行之间的 TOCTOU 上下文替换。列表、详情和取消端点均由工作空间作用域约束。
- `OllamaChatModelProvider` 调用本地 `/api/chat`，关闭流式输出并传入 Pydantic JSON Schema；模型
  输出同时经过 Schema 与引用归属校验，首次失败只修复重试一次。
- `OpenAICompatibleChatModelProvider` 仅接受 HTTPS 基础地址，通过 `/chat/completions` 发送 Bearer
  凭据和 strict JSON Schema 请求，禁用重定向并校验结构化响应。API Key 由 Worker 子进程直接从操作
  系统 keyring 读取，不进入 SQLite、任务/进程参数或日志；认证、限流、超时、服务不可用、拒绝及无效
  响应均映射为安全、可恢复的任务错误，且不会回退到本地 Provider。
- Worker 监督覆盖取消、超时、非零退出和应用重启后的中断恢复；Prompt 将文档片段明确标记为
  不可信资料，不记录或回显完整 Prompt。
- 测试设计 API 包含运行快照读取、问题确认、测试点生成/更新、结构化用例生成/更新和用例批量状态更新，
  全部先通过分析服务执行工作空间与运行作用域校验，并只接受 `passed` 运行。两级转换使用已冻结的分析
  结果在本地确定性完成，不启动 Worker、不读取模型凭据，也不产生新的模型请求。测试点生成后确认记录
  不可修改；用例生成后来源测试点不可修改。批量状态更新先验证全部用例归属，再在同一事务内提交。
- 测试设计快照同时从冻结分析问题及现有确认、测试点和用例实时派生追踪矩阵，不新增数据库表。每行
  保留稳定引用并由应用层统一计算 `unreviewed | excluded | accepted | test_point | case_draft |
  covered | disabled`，前端只负责汇总、筛选和展示，避免客户端重复推断覆盖语义。
- 同一快照由应用层按 `TestPointType` 派生自动化建议，返回 `recommended`、`suggested_type`、稳定
  `rule_id` 和用户可读原因。性能使用 `performance_api`，异常/边界/状态/权限使用
  `repeatable_api`，正向/兼容使用 `manual_context`。新对象在服务端继承建议；现有对象应用建议仍走
  原测试点或用例更新 API，避免绕过校验与锁定规则。
- HTTP 执行 API 管理工作空间作用域的环境、普通变量、安全变量引用和执行历史。`20260815_0010`
  创建 `http_environments` 与 `http_executions`，`20260816_0011` 增加断言快照、断言结果和有序事件表；
  运行记录冻结环境名、Base URL、普通变量、已配置安全变量名称、请求模板、最大尝试次数和断言，但不
  保存安全变量值。安全变量通过单用途 API 写入 keyring，前端 Store 不持有值。
- HTTP Runner 使用独立 `spawn` Worker。子进程按冻结的安全变量名称从 keyring 读取当前值，展开
  `{{NAME}}` / `{{secret.NAME}}` 后通过标准库传输适配器发起请求；展开结果不回写数据库或日志，也不进入
  `Process.args`。传输层禁止自动重定向，限制请求体 1 MiB、响应体 2 MiB，并对标准敏感响应头和已知
  安全变量值二次脱敏。GET/HEAD/OPTIONS 仅对传输超时或服务不可用执行最多 3 次尝试；断言失败保留
  响应并进入 `failed`，Runner 故障进入 `error`/`timeout`。Supervisor 负责取消、总超时、非零退出和
  重启恢复。运行事件仅保存稳定代码和静态安全消息；重跑从历史运行的冻结模板创建新运行。
- `20260816_0012` 创建 `websocket_executions` 与 `websocket_execution_events`。WebSocket Runner 复用
  HTTP 环境元数据和 keyring 安全变量，将冻结的 HTTP/HTTPS Base URL 映射为 ws/wss；子进程展开路径、
  握手头和消息模板，代理被禁用，文本和二进制响应分别以 UTF-8 与 Base64 脱敏持久化；Supervisor 负责
  取消、130 秒总超时、非零退出和重启恢复。
- `20260816_0013` 创建 `proto_assets`，按工作空间冻结文件元数据、SHA-256 和 FileDescriptorSet。
- `20260816_0014` 创建 `protobuf_executions` 与 `protobuf_execution_events`，冻结描述符、环境、RPC、
  请求和断言；表内仅保存安全变量名称，不保存 keyring 值。
- `20260816_0015` 为 WebSocket 运行冻结追加发送消息、接收数量、Ping 心跳、重连上限和消息断言，并
  持久化有序响应、断言结果与实际连接尝试次数。Runner 每次连接按序重放完整发送序列，再按序接收指定
  数量；仅连接超时或不可用可重连一次，消息超限和断言失败不重连。0015 之前已有的单消息响应会在读取
  时映射为序列中的第 0 条，升级后仍可查看历史结果。
- `GET /api/workspaces/{workspace_id}/task-events` 使用 WebSocket 聚合最近每类最多 100 个任务快照，覆盖
  文档解析、分析、HTTP、WebSocket 和 Protobuf。每条连接使用独立 `stream_id` 与单调 `sequence`；
  首帧为 `stream_ready`，后续仅在状态、进度或变更时间变化时发送 `task_updated`。事件不包含模板、
  响应正文、错误详情或密钥；前端据此刷新原详情 API。此切片不新增数据库表，也不是持久化消息总线。
- 浏览器 WebSocket 无法设置 Authorization Header，因此桌面会话令牌使用 Base64URL 编码的第二个
  `Sec-WebSocket-Protocol` 值传入；服务端恒定回选公开协议 `ai-qa-task-events`，令牌不进入 URL、响应
  子协议或应用日志。前端对同一流去重，发现序号缺口或新流时刷新当前活跃任务，并按 0.5-8 秒退避重连。
- `GET /api/workspaces/{workspace_id}/report` 从现有分析、测试设计和三类接口执行表即时派生只读报告，
  不新增数据库表。`POST /api/workspaces/{workspace_id}/report/render` 以同一 Schema 生成 JSON、Markdown
  或独立 HTML；快照只包含冻结目标摘要、状态、时长、断言统计、稳定失败原因和安全事件，不包含请求/
  响应正文、Header、普通变量或凭据值。renderer 对文本再次执行敏感字段、Bearer、邮箱和手机号脱敏，
  Markdown 转义表格/HTML 字符，HTML 对所有动态文本进行实体转义。
- 报告快照 Schema v2 固定返回截至生成时间的最近 14 个 UTC 自然日；只有带完成时间的终态进入日趋势，
  取消保留为单独计数但不进入通过率与平均时长分母。失败归因在领域层按“超时优先，再匹配稳定错误码”
  的固定规则生成分类、规则 ID 与中文理由，不读取错误正文、不调用模型，也不发生外发。
- Electron preload 只新增固定的 `saveReportFile` IPC 方法。主进程重新校验格式、扩展名、媒体类型、
  文件名和 10 MiB 内容上限，再由系统保存对话框取得目标路径；后端与 renderer 均不能指定任意落盘路径。

## 8. 本地安全

- FastAPI 启动时生成随机端口和一次性会话令牌，通过安全 IPC 交给前端。
- Electron renderer 启用 sandbox 和 context isolation，关闭 Node integration；preload 只暴露按方法定义的最小桥。
- IPC handler 校验发送方 URL；开发态只信任 `http://127.0.0.1:1420`，生产态只信任 `app://ai-qa-assistant`。
- 默认拒绝渲染器权限请求、新窗口和非受信导航，并通过 CSP 限制脚本、连接与资源来源。
- 仅允许 Origin 为桌面应用的请求。
- 文件路径统一经过 `resolve` 和工作空间边界检查。
- 外部命令使用 allowlist 适配器；默认禁止任意 Shell。
- API Key 存在系统凭据库；当前单例模型凭据使用固定 service/account，数据库不保存凭据值。
- 报告、日志、Prompt 进入模型前执行脱敏策略。

## 9. 打包

- 前端由 Vite 构建。
- FastAPI、迁移脚本、Python Worker 和 `grpcio-tools` 由 PyInstaller onedir 打包为独立 Sidecar；冻结态
  Protobuf 编译通过 Sidecar 内部分发入口运行，不依赖系统 `protoc` 或项目 `.venv`。
- Electron Forge package 将 Sidecar 目录作为只读 resources；打包态数据库固定写入 Electron
  `userData/data`，启动握手前执行 Alembic upgrade，迁移失败不开放本地 API。
- Electron 每秒更新会话专属父进程心跳文件；Sidecar 在心跳缺失或超过 5 秒后安全停止，避免桌面主进程
  崩溃后遗留本地 API。API 仍只监听随机 `127.0.0.1` 端口并使用高熵会话令牌。
- Electron Forge package 生成自包含桌面目录；Windows make 使用 Squirrel.Windows 生成 Setup.exe、
  full.nupkg 和 RELEASES，并对 make 目录内全部发布制品生成 `SHA256SUMS.txt`。当前制品未签名，仅供内部验证。
- 主进程最早阶段处理 Squirrel 安装、更新和卸载启动事件，并设置稳定 App User Model ID，避免安装期间
  额外启动业务窗口。事件处理由仓库内 TypeScript 模块实现，不依赖 pnpm workspace 根目录中可能未被
  Forge 收入 ASAR 的提升运行包。CycloneDX SBOM、脱敏发布元数据和 PFX 签名/时间戳门禁已接入；
  GitHub hosted Windows runner 的安装生命周期已观察通过，正式证书实际签名仍待完成。
- package 前按 Electron npm 包内置的官方 SHA-256 校验 ZIP；优先使用显式制品目录，否则查找系统下载
  缓存。Forge 只接收校验通过的本地 ZIP 目录，避免不同镜像 URL 的缓存目录导致无意义重复下载。
- 本地 API 绑定地址由统一规则固定为规范 IPv4 回环 `127.0.0.1`；`0.0.0.0`、局域网地址、IPv6
  通配/回环和 `localhost` 别名都在 Uvicorn 启动前拒绝。桌面 Sidecar 启动后还会读取真实 listener
  socket 地址，非 `127.0.0.1` 时不输出握手并终止启动。
- renderer 保持 `sandbox: true`；preload 必须编译为不依赖相对模块加载的单文件桥，生产资源从
  `app://ai-qa-assistant` 加载。
- 每个平台独立构建和签名，不进行跨平台交叉打包。
