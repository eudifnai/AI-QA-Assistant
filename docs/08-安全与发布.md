# 安全与发布

## 1. 威胁范围

重点防护：恶意文档、路径穿越、命令注入、Prompt Injection、密钥泄露、日志泄露、桌面本地 API 被其他进程调用、自动更新被篡改。

## 2. 安全控制

- 文档解析 Worker 使用独立进程和资源上限。
- HTML 不执行脚本；PDF/Office 解析不启用宏。
- 检索内容作为“不可信资料”进入 Prompt，不允许覆盖系统指令。
- 外部命令使用明确适配器和参数 allowlist。
- 本地 API 使用随机端口、启动令牌、Origin 校验和短生命周期。
- API 绑定只接受规范 IPv4 回环 `127.0.0.1`，不接受通配、局域网、IPv6 或 `localhost`；桌面服务
  只有在真实 listener 地址再次校验为回环后才输出包含端口和令牌的启动握手。
- Electron renderer 保持 sandbox、context isolation 和 `nodeIntegration: false`；preload 不暴露原始 IPC。
- Electron IPC 校验 sender，生产资源只通过 `app://ai-qa-assistant` 加载，拒绝新窗口、权限请求和非受信导航。
- sandbox preload 不加载相对本地模块，只注入固定方法和固定 IPC channel；打包回归测试会阻止重新引入
  沙箱中不可用的相对 `require`。
- Electron package 只复用文件名和官方 SHA-256 同时匹配的运行时 ZIP；显式制品目录与系统下载缓存采用
  相同校验，不按文件名盲目信任本地制品。
- 打包态 Sidecar 位于只读 Electron resources，业务数据库只写入 `userData/data`；启动时先执行捆绑的
  Alembic 迁移，成功后才输出随机端口和会话令牌握手。
- Electron 使用会话专属临时心跳文件证明桌面主进程存活；心跳缺失或超过 5 秒时 Sidecar 停止，避免
  主进程崩溃后留下可访问的本地 API。心跳只包含 Electron PID，不包含令牌、路径数据或用户内容。
- Sidecar 与冻结 Protobuf 编译器均以参数数组启动，不使用 Shell；打包态不搜索仓库、`.venv` 或系统
  `protoc`。
- Squirrel make 制品生成后写入 SHA-256 清单并由门禁重新计算验证；校验和只证明制品完整性，不代表
  发布者身份。未通过 Authenticode 验证的 Setup 必须明确标记为内部候选，不得冒充正式签名版本。
- make 同步生成确定性 CycloneDX 1.6 SBOM 和脱敏发布元数据；SBOM 子进程会剥离证书环境变量，
  元数据只记录 `pfx` 或 `unsigned_internal_candidate` 模式，不记录证书路径、口令或 Secret 名称对应值。
- PFX 路径和口令必须成对注入，签名配置使用 `continueOnError: false`。元数据声明 `pfx` 时，发布门禁
  强制校验 Setup 与 full.nupkg 中全部 PE 文件的有效 Authenticode 签名和可信时间戳。
- Squirrel 安装、更新和卸载事件由主进程最早处理，事件期间不启动 FastAPI Sidecar 或业务窗口；
  快捷方式命令脱离主进程运行，应用最多 1 秒后退出，不等待 `Update.exe` 关闭。
- 安装后冒烟专用环境变量只接受系统临时目录内以 `ai-qa-acceptance-` 开头的 JSON 路径；证据在 Sidecar
  安全握手、数据库迁移和 renderer 加载完成后原子写入，固定记录 `api_host=127.0.0.1`，不包含端口、
  会话令牌或凭据。生命周期脚本始终使用系统临时绝对路径，再把结果归档到调用者指定目录。
- 卸载门禁要求主程序和卸载项消失；仅允许 Squirrel 的固定墓碑残留，记录后清理测试安装根。未知文件、
  目录或仍在运行的主程序均视为失败，用户数据库按当前策略保留。
- 报告导出前再次脱敏。
- 云模型调用展示 Provider、模型、发送内容范围和隐私提示。

## 3. 发布流程

1. 冻结版本和功能范围。
2. 更新版本号、迁移、用户文档和 CHANGELOG。
3. 执行完整 CI 与端到端测试。
4. 在干净虚拟机验证安装、首次启动和卸载。
5. 从上一稳定版验证升级和数据迁移。
6. 生成安装包、SBOM、校验和并签名。
7. 发布候选版，完成小范围验证。
8. 发布稳定版并保留回滚安装包。

首个公开版本没有上一稳定版时，第 5 步记录为“不适用”，不得用同版本或人工伪造制品替代升级证据；
首次发布必须归档可回滚安装包，并从下一版本开始把该步骤恢复为正式发布阻塞门禁。成功的非 PR
Windows CI 会在仓库 Actions artifact 中保留六项发布制品 90 天；生命周期 JSON 不随制品上传。

## 4. 数据升级

- 应用启动前备份 SQLite。
- Alembic 迁移失败时不继续启动业务服务。
- 数据目录版本与应用版本分别记录。
- 降级不自动执行逆迁移；使用备份恢复。

## 6. 工作空间记录删除

- 桌面端删除前必须明确提示并二次确认。
- 当前删除能力只移除 SQLite 中的工作空间记录，不删除、不清空也不移动用户目录。
- 未来如增加磁盘数据删除，必须单独列出原文件、数据库、缓存和向量索引的删除范围与恢复策略。

## 7. 模型配置与需求分析

- SQLite 仅保存 Provider、模型名、基础 URL、模式和云端数据同意状态，不保存任何凭据值。
- 设置 API 拒绝未声明字段，防止客户端误将 API Key、Token 或密码写入业务数据库。
- 本地模式仅接受回环地址且不得自动回退云端；云端模式必须使用 HTTPS 并显式确认潜在数据外发。
- 模型 API Key 只通过单用途接口写入 Python `keyring`，状态和写入响应都只返回布尔值；清除操作
  同时删除系统凭据库条目。
- 前端密钥输入在请求结束后立即清空，Store 不保存密钥；验证错误详情不包含请求输入值。
- 本地需求分析页展示 Provider、模型、回环地址和数据范围；只有用户主动点击后才向 Ollama 发送所选
  文档版本的稳定引用片段。Provider 与 Worker 都校验目标为 `localhost`、`127.0.0.0/8` 或 `::1`。
- 云端模式要求先保存设置级数据外发同意，并在每次分析前逐次确认被冻结的 Provider、模型、完整 HTTPS
  请求 endpoint（`base_url` 加 `/chat/completions`）、文档版本、全部稳定片段数和字符数；运行记录
  同时冻结 `base_url`。本次确认只对该次任务有效；POST 携带版本、Provider、模型、`base_url`、
  `input_chunk_count` 和 `input_character_count` 快照，后端发现任一项变化都拒绝任务并要求重新确认，
  避免 TOCTOU。
- 每次运行在 `analysis_runs` 中审计 `base_url`、`input_chunk_count`、`input_character_count` 和
  `cloud_data_confirmed_at`；这些字段由 `20260812_0007` 迁移加入，但数据库不保存 API Key。
- OpenAI-compatible Provider 只接受 HTTPS，通过 `/chat/completions` 发送 Bearer 凭据和 strict
  JSON Schema 请求，并禁止 HTTP 重定向。API Key 由 Worker 子进程直接从操作系统凭据库读取，不进入
  SQLite、Worker 进程参数或日志。
- 本地与云端之间没有自动回退。认证、限流、超时、服务不可用、模型拒绝或无效响应只记录不含密钥和
  原始响应的稳定错误码与中文说明，用户修复配置或服务状态后可重新发起。
- 文档内容作为不可信资料进入系统约束下的 Prompt；模型输出必须通过固定 Pydantic Schema，每个问题
  至少关联一个属于当前文档版本的引用片段。校验失败最多修复重试一次。
- 单次分析输入上限为 200,000 字符，超限明确拒绝，不截断、不改用云模型；完整 Prompt、文档内容和
  模型原始响应不写入日志。
- 问题确认说明与测试点属于本地业务数据，保存在 SQLite；测试点只引用已有分析问题，不复制 API Key
  或模型原始响应。确认到测试点的转换不调用模型、不读取凭据、不外发数据。每个来源问题有唯一测试点，
  且测试点生成后确认结论锁定，防止审计依据被无痕修改。
- 结构化测试用例及其步骤同样只保存在 SQLite；每个已确认测试点最多生成一个用例。生成不调用模型、
  不读取凭据、不外发数据；用例生成后来源测试点锁定，批量确认或禁用在一个数据库事务内完成。
- 需求追踪矩阵是当前分析运行冻结数据的只读派生视图，不新增持久化副本、不调用模型、不读取凭据，
  切换工作空间或运行时通过请求代际校验丢弃旧快照。
- 自动化候选建议同样只由本地枚举规则派生，不读取需求正文之外的新数据、不调用模型、不创建脚本或
  启动执行。对已有草稿的应用必须由用户显式触发，并复用原更新接口的作用域与锁定校验。

## 8. 数据库备份与诊断

- 手动备份只导出 SQLite 业务数据库，不扫描或复制用户工作空间，也不访问 keyring 凭据值。
- 备份目录固定在数据库同级 `backups/`，服务端自行生成文件名；客户端不能传入源路径或目标路径。
- 备份使用 SQLite 一致性快照并在发布文件前执行完整性检查，失败仅返回脱敏错误和 `trace_id`。
- 诊断页面会显示本机数据库绝对路径，属于本地用户可见信息；API 仍受桌面会话令牌保护且只监听回环。
- 当前版本不提供恢复、备份删除或自动备份，避免在缺少二次确认和完整回滚验证时执行破坏性操作。

## 9. 文档导入

- 文件必须由用户通过系统选择器明确选中，并在服务端真实路径校验后确认位于目标工作空间内。
- 当前只允许 `.md/.txt/.docx/.pdf` 且最大 10 MiB；路径越界、格式不支持、超限、损坏编码或容器
  使用稳定错误码。
- 数据库保存相对路径、哈希、解析文本及引用片段，不复制原文件；引用片段仅保存本地来源范围、字符偏移
  和稳定 ID，源文件内容不会隐式发送到模型或网络。
- Worker 在独立进程中运行并受超时监督；取消只终止对应任务进程，不删除源文件或已有版本记录。
- 文本预览按 Vue 文本插值与 `<pre>` 渲染，不作为 HTML 执行。
- 引用片段由后端按文档所属工作空间校验后读取；renderer 不得通过引用 ID 绕过工作空间作用域。
- 拖拽路径由 sandbox preload 调用 `webUtils.getPathForFile` 生成；不信任 DOM 自定义路径或 renderer 直接
  构造的字符串。所有路径仍必须经过后端真实路径、工作空间边界、格式、大小和哈希校验。
- 单批最多 50 项且不递归展开目录；预期文件错误按项返回，意外异常不得降级为包含调试详情的批量结果。
- DOCX 不执行宏，并在解析前限制 ZIP 条目数和解压总量；PDF 不解密、不执行嵌入内容且不调用
  OCR。解析器限制页数、结构块和输出字符数，防止小型压缩容器产生无界文本结果。

## 10. HTTP 环境与执行

- HTTP 环境和执行记录按工作空间作用域校验；Base URL 只接受 HTTP/HTTPS 且拒绝 userinfo、query 和
  fragment，请求路径不能替换目标 Origin。HTTP Runner 禁止自动跟随重定向且不隐式使用系统代理，
  避免凭据被带到用户未选择的中间或新目标。
- 普通变量进入 SQLite；安全变量值只经单用途本地 API 写入 keyring，SQLite 仅保存名称。前端请求结束
  后清空输入，Pinia 不保存值；Worker 子进程按环境 ID/名称读取，展开值不进入进程参数或日志。
- 删除环境前必须二次确认，并先清除该环境关联的 keyring 条目；执行历史保留冻结的非敏感环境和模板
  快照。若排队后安全变量被删除或凭据库不可用，任务安全失败，不使用其他值或目标回退。
- 请求体最大 1 MiB，响应最大 2 MiB；二进制响应以 Base64 保存。标准敏感响应 Header 整体替换为
  `***`，响应头/响应体中出现的本次已知安全变量值在持久化前替换为 `***`。
- 连接错误、请求超时、响应超限、Worker 崩溃和应用中断只写稳定错误码与中文消息，不记录目标响应
  错误正文、展开后的请求或凭据值。
- 自动重试只允许 GET/HEAD/OPTIONS，且仅针对传输超时或服务不可用，最多 3 次；鉴权、限流、业务响应、
  断言失败和非幂等方法不重试，避免重复副作用。事件日志只持久化稳定代码和静态安全消息。
- 终态重跑复用原运行冻结的目标、模板、尝试上限和断言；若原环境已删除则拒绝，且每次重跑创建新的
  可审计运行记录，不覆盖原始结果。

## 11. WebSocket 执行

- WebSocket 复用已验证的 HTTP/HTTPS 环境并确定性映射为 ws/wss；路径不能替换 Origin 或包含 fragment，
  客户端禁用系统代理，避免凭据经未选择的代理或目标外发。
- 安全变量仅由 Worker 子进程从 keyring 读取并展开到握手头或发送消息，不进入 SQLite、进程参数或日志；
  接收文本/二进制中出现的本次已知安全变量值在持久化前替换为 `***`。
- 单条发送文本限制 1 MiB、一次最多 10 条且发送总量限制 2 MiB；最多有序接收 20 条，每条及总量均
  限制 2 MiB。握手失败、连接失败、超时、超限和异常关闭只返回稳定错误码与静态中文消息，不记录
  展开后的 URL、Header、消息或上游错误正文。
- 自动重连默认关闭且最多一次，只处理连接超时或不可用；不会对超限或断言失败重连。每次重连会重新
  发送完整序列，因此 UI 必须展示可能重复触发远端副作用的警告，由用户显式配置后才启用。

## 12. 统一任务事件流

- 事件流只监听随机回环后端端口，Electron CSP 仅额外开放 `ws://127.0.0.1:*`，不开放任意外部 WebSocket。
- 会话令牌以 Base64URL 子协议值传递，不进入连接 URL；后端固定回选公开协议名，不回显令牌。无效令牌
  使用静态 1008 关闭原因，事件载荷与日志均不包含令牌。
- 每条事件只包含任务标识、工作空间、统一状态、进度和 UTC 生命周期时间戳，不推送用户文档、Prompt、请求/
  响应正文或错误详情。详细内容继续通过带 Bearer 认证和工作空间校验的 HTTP API 获取。
- 客户端只接受协议版本 1、已知任务类型/状态和单调序号；重复事件忽略，序号缺口或重连触发作用域恢复。

## 13. Protobuf 资产与编解码

- `.proto` 必须由用户通过专用系统选择器选择，并通过真实路径工作空间边界、`.proto` 后缀、1 MiB
  大小和 SHA-256 校验；描述符在 SQLite 中按工作空间持久化。
- `grpcio-tools` 通过当前 Python 解释器和参数数组启动，`shell=False`，有固定超时且不返回原始编译器
  stderr。系统不加载生成代码，也不调用工作空间内的 Python 模块。
- 首切片编译前拒绝所有非 `google/protobuf/` import，标准 include 固定来自已锁定的 `grpcio-tools`
  包。编译后再次检查源文件，哈希、路径或大小变化时不发布描述符。
- 资产编解码必须携带 SHA-256 快照；JSON 输入上限 1 MiB，Protobuf 二进制上限 2 MiB。临时编解码的
  JSON、Base64 和二进制不写入 Proto 资产表或日志。
- 网络执行会在独立运行记录中冻结请求 JSON、描述符、目标、RPC 和断言，但只保存安全变量名称。安全值
  由 Worker 子进程从 keyring 读取，不进入 SQLite、进程参数或日志；响应头及解码后的字符串字段在落库前
  脱敏。HTTP 传输禁用系统代理和重定向，并强制 `application/x-protobuf`。

## 14. 报告导出

- 报告读取和渲染 API 必须携带工作空间 ID，并在读取任何运行记录前验证工作空间存在；三类执行、分析和
  测试设计统计全部按该工作空间过滤。
- 报告只使用现有已脱敏记录的安全摘要，并在格式化前再次屏蔽敏感字段赋值、Bearer、邮箱和手机号。
  请求/响应正文、Header、普通变量值、安全变量名称和 keyring 内容均不进入报告快照或导出内容。
- JSON、Markdown 和 HTML 共用版本化快照；Markdown 转义表格分隔符和 HTML 字符，HTML 对所有动态文本
  做实体转义，不加载远程脚本、样式或资源。
- schema v2 的 14 日趋势仅从已过滤工作空间内带完成时间的终态派生。本地失败初步归因只读取执行状态
  和稳定错误码，按固定优先级输出规则 ID 与静态理由；不读取错误正文、不调用模型、不访问网络，未知
  分类必须在界面和导出中提示人工复核。
- renderer 无文件系统写权限且后端不接受导出路径。sandbox preload 只转发固定报告对象，Electron 主
  进程验证格式、媒体类型、扩展名、纯文件名和 10 MiB 上限后才展示系统保存对话框并写入用户选择的位置。
- 用户取消保存不产生文件且不视为任务失败；报告正文只在渲染响应和一次 IPC 调用中短暂存在，不进入
  Pinia、SQLite 或应用日志。
